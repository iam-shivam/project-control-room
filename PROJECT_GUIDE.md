# How to organize any project

1. Open the website and click **New project**.
2. Choose **Software**, **AWS**, **Learning**, or **Blank** template.
3. Open the project **Overview** to see progress and upcoming tasks.
4. Use **Tasks** to track milestones. You can add custom task groups and priorities.
5. Use **Files** to upload screenshots, PDFs, designs, checklists, Markdown, or source-code exports. Uploaded files stay in this browser, not in GitHub.
6. Use **Notes** for architecture plans, context, meeting notes and decisions.
7. Use **Links** for the project's real GitHub repo, product URL, Google Drive folders, or documentation.
8. Visit **Backup & settings → Export full backup** to create a portable copy. Import it on another browser to continue the workspace there.

## Example projects

| Project | Useful tasks | Useful files / links |
|---|---|---|
| AutoBot | Fix order execution, testing, deployment | QA docs, architecture, GitHub repo |
| AWS operations | Verify RDS deletion, budgets, billing correspondence | AWS docs and billing support links (avoid public identifiers) |
| Portfolio | Hero design, accessibility, deploy | Screenshots, references, design files |
| Learning plan | Daily topics, coding exercises, review | Markdown notes, code examples |

## What is not included

This is **not** a GitHub code uploader, file synchronization service, or replacement for a secure document repository. It helps you track documents locally. If you want a central online file library for multiple users, add an authenticated backend and object storage (e.g., S3 or another provider) after designing privacy and cost controls.
